## 0. The mask and its production
- **"Passed" definition:** `getPPIncrement` (`cpp_bitboard.cpp:7979-8149`). Forward span = own file + both
  neighbours, ranks ahead (`passed_span_white/black[sq]`). Marked passed iff **zero enemy pawns in the 3-file
  span**. The mask bit is set **before** any blockade/support conditioning; conditioning affects only the
  returned `ppIncrement`, never the mask.
- **Timing quirk:** masks are populated incrementally during the pawn loop (pawns evaluated first, ascending
  square). Piece evaluators run after → see the complete mask; but the ±100 passer-attack checks INSIDE
  `evaluate_pawns_*` see a **partial mask** (scan-order dependent, systematically asymmetric W vs B).
- **Raw-mask consumers: 13 sites**, none realizability-conditioned (mask membership = classic def only).
  (`evaluate_kings_midgame` takes the masks as params but never reads them.)

## 2. OVERLAP / DOUBLE-COUNT map
A single advanced defended White passer is credited in **up to 9 live channels at once**:
1. ppIncrement supporter terms land in the rank bonus TWICE (table selector AND `+ppIncrement>>3/>>2`).
2. `getPPIncrement` supporters vs `boost_pieces_...` (#16): direct overlap, two formulas, two terms.
3. Rook-behind-passer triple count (#8/#10 file + #9/#11 attack-loop + #16 path-attacker). (The extra 35-pt eg double-count in #10 is neutralized by default — `ENABLE_ROOK_DBLCOUNT_FIX=true` — so it's NOT part of the live over-read.)
4. Piece-proximity ±100 blocks re-credit the rank bonus; midgame blocks pay the same for OWN vs ENEMY passer → inflation when both sides touch it.
5. #18 (`ae_passer`) vs #19 (`passer_realizability_delta`): verbatim duplicate; de-duped by the KRACE skip.
6. #18 vs #17: both price "close-to-promo × realizability × defender-king"; can double-price if both enabled at the mid/end boundary.
7. #18 re-derives `ppIncrement` → supporter/blockade credit counted AGAIN inside `ae_passer`, ×~13, on top of the (unclamped) endgame rank bonus already in `pt_pawns`.
8. #22 reuses the UNCLAMPED rank bonus as capture value (sign is correct by default via `ENABLE_CAPGAIN_PAWN_FIX=true`; the concern is the UNCLAMPED magnitude, not the sign).
9. #20 releases draw damping on raw advancement while 1-8 also credit the same passer.

## 3. CONDITIONING GAPS
**In DEFAULT config the only path-attack conditioning anywhere is `passer_danger` (off) + the zeroed enemy half
of #16 — i.e. effectively ABSENT.** King-race conditioning exists only inside the deep-endgame gate (#18).
Midgame: a passer whose entire path is enemy-controlled scores ~the same as a clean runner, minus ≤30 pts.
**The discriminator between P3 (legit runner) and fen3/P1/P2 (over-reads) is exactly the MISSING signals —
path-attack control + defender-king/piece coverage of the promo path — NOT magnitude.**

## 4. RAW-MASK propagation — confirmed
`white/black_passed_pawns` carry ZERO conditioning (span-emptiness only) and are consumed by 13 sites across
`pt_pawns/knights/bishops/rooks/queens/kings`, `passed_pawn_support`, (gated) `passer_danger`,
`endgame_convertibility_scale`. The one genuinely-conditioned verdict (`ppIncrement`) is consumed by exactly
ONE scorer (the rank bonus) and thrown away; every other channel re-decides worth from scratch or not at all.

## 5. Candidate coherent-redesign directions (NOT implemented)
1. **Single per-passer verdict struct**, computed once after the pawn loop (masks complete): `{sq, adv,
   support/blockade (ppIncrement-style), path_attacked_count (reuse `passer_danger` D2 + attack_bitmasks, in the
   tail where they're populated), king_catch (square rule + tempo), stop_secure}` → collapse to one scalar
   realizability `R ∈ [0,256]`.
2. **One scorer, many consumers.** `base(adv) × R/256` in `pt_pawns` (or a single `passer` term); every other
   channel reads an `R`-weighted `passer_weight[sq]` (0..256) array instead of the raw bit — preserves the
   per-piece hooks but makes ONE verdict authoritative (the interpretable analog of SF's single conditioned
   `passed`).
3. **Kill the pure double-counts first** (cheap): (a) drop own/enemy symmetry of the midgame ±100 blocks or fold
   into #16; (b) make #16 read the verdict not re-walk the path; (c) feed #22 the CLAMPED rank bonus (sign is
   already correct by default via `ENABLE_CAPGAIN_PAWN_FIX=true`; the issue is the UNCLAMPED magnitude).
4. **Extend `passer_danger`'s D2** (the only existing path-attack code) into the shared verdict rather than a
   separate additive term — its BLOCK[] + attack_bitmasks approach IS the missing signal, costs ~nothing.
5. **P3 keep-out guard:** dock R only for UNCONTESTED enemy control (as D2 does), credit own control → P3-style
   clean runners keep R≈256 while fen3/P1/P2 collapse toward the floor.
